# Incident notes: invoice PDFs failed to generate (SEV-2)

Written by the incident lead after the incident. Times are local, Asia/Kolkata (UTC+05:30).

- 21 Oct 2026, 18:00: release 2026.10.21-3 deploys the invoice service. It upgrades the PDF
  library from 4.2 to 5.0. Deployed commit `5e8d1a0`.
- 18:03: first `FontNotFound` errors in the invoice service logs.
- 18:17: an accountant at a customer emails support: "no invoice PDFs since 6 pm". Nobody was
  paged; the first error came 14 minutes earlier.
- 18:25: on-call confirms that every invoice PDF request fails with HTTP 500 (2,140 failures by
  18:40).
- 18:31: on-call rolls the invoice service back to 2026.10.20-1.
- 18:38: PDFs generate again. Failed invoices are regenerated by a manual job by 19:30.

What we know:

- PDF library 5.0 no longer bundles the default font; our container image installs no fonts.
  Reproduced in staging with 2026.10.21-3: every PDF fails with `FontNotFound`. With a font
  package installed, all 200 test PDFs generate.
- Someone suggested the storage account was throttled. Storage metrics show 0 throttled requests
  and normal latency from 17:30 to 19:00.
- The release pipeline runs unit tests only; no test generates a real PDF.

Invoices are a core journey for finance customers and there was no workaround during the
incident.
