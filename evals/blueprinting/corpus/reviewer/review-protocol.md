# Reviewer/controller protocol — not worker input

Candidate budgets and criteria require separate source-grounded review before any attempt. This
development/initial-comparison tranche is not complete qualification and authorizes no runs itself.
The separate held-out/reliability set must be independently authored, reviewed and frozen before
its outputs are generated. Case order for later use: manufacturing, service, finance, presales,
rfp; stage order is lexicographic numbered file order, never adjusted after seeing worker output.
Source releases: initial protocol+brief → preparation checkpoint → stage 1 → questions/replies →
checkpoint → next numbered stage, repeated → final selected outputs. No actor may insert sources.
Answer release follows answers.md and deterministic topic counting/matching in topics.md; stage 0
prepares but consumes no stakeholder slots and is not automatically replayed. Log every released
file/reply hash and timestamp. Independent cases use fresh worker contexts; manufacturing retains
its own prior stages and stable record.

## Equal budgets and comparison

Predeclare and record these limits and any run-plan changes within existing authority before
attempts; no renewed owner budget-approval gate is added. Only exceeding existing authority or
taking external effects requires the applicable additional approval. Changes never erase prior runs.

For **each case and each arm**: same model, mode, reasoning effort, general instructions, stage
inputs, elapsed-time policy, tools/output capabilities and environment; one first attempt, zero
delegation, 75 active minutes, 100 tool calls, four topic questions per stage. There is no corpus
allocation borrowed from another case. Manufacturing has three stages in both arms; others two.
Reads, generation, local scripts, export attempts and questions consume the budget. Only waiting
for controller input pauses time. No browsing/paid third-party call/external write. Record model ID
and actual versions at run time; no model pinned here. Baseline lacks Blueprinting/domain skill
instructions, templates and helper scripts; ordinary document tools remain available to both arms.
This compares workflow bundles, not bare model intelligence. If isolation fails, record contamination.

Exact tokens/provider dollars are **unavailable in this corpus**; future host telemetry may or may
not expose them. Capture only actually available usage and label absent fields unavailable, never
zero. These common caps do not prove equal realized cost; no efficiency or savings win is justified
without measurement and enforcement. Record wall time, active time, tool calls, question topics,
export failures and any cap-enforcement limits. Budget exhaustion fails applicable completion checks;
external interruptions are blocked, not wins. Retain partial outputs and original attempt IDs.

There are zero automatic retries. After absolute first-attempt assessment, at most **one separately
labelled repair per arm per case**, with identical source-backed feedback policy, 30 active minutes,
40 tool calls, no new stakeholder facts/questions or delegated workers. Do not substitute repair
scores for original scores. If unused repair budget differs, report it; do not imply equal cost.

Judging budget, separate from worker budget: six calibration examples once per judge configuration;
then two fresh absolute single-output judgments plus two fresh pairwise judgments with reversed
order per case = 20 assessment calls for ten initial outputs, plus six calibration calls. Each call
maximum 20 active minutes and 30 read-only tools, no delegation/external writes; token cap unavailable.
Repaired pairs, if both supplied, receive the same four-call process, reported separately. If only
one is repaired, assess it absolutely without inventing a paired win. Failed calibration blocks that
configuration from supplying acceptance evidence. Retain failed calls; any new configuration and
its recalibration need a predeclared recorded run-plan/resource change within existing authority,
or applicable approval if that authority would be exceeded. No silent retries.

Lock absolute judgments before pairwise calls. Label artifacts with neutral IDs, conceal arm/model
mapping and prior scores. Preserve substantive formatting and caveats; record recognizable cues.
Reversed-order disagreement is instability, not something to average into victory. Compare by case
and dimension; better/worse/tied/inconclusive is independent of absolute pass. No universal claim.

## Evidence and ownership

Before runs: source reviewer checks all material key facts, authority, relationship oracles, unknown
product fit, numeric inputs, answer matching and alternatives. Check that an output can be useful
without violating policy. Record reviewer identity, manifest hash, unresolved findings and disposition.
The author cannot self-certify this review. An accurate supported alternative missing from this key
triggers versioned adjudication, not an invented stakeholder answer or automatic failure.

During review each finding needs output span, source span, criterion, severity, consequence and
smallest repair. Plain wording preserving an exception beats a polished unsupported claim. Score
all applicable dimensions independently; no average overrides a hard failure. Renders/editability
are assessed from actual bytes and observed edits, never from an author's “editable” declaration.
Business decision, consultant review, publication approval and observed delivery are separate gates.

Afterwards: retain inputs/answers, exposed paths, outputs/hashes, clocks/usage, absolute judgments,
pairwise order/results, dissent, repairs and integration evidence. Review 1 → repair/revalidation →
fresh Review 2 → owner value/real handoff judgment remain unexecuted. No cloud effects are needed
for the semantic keys. Missing native exports are not silently passed; integration owner records
actual blocked/unavailable outcomes and required next checks. Fixture review is not release approval.
