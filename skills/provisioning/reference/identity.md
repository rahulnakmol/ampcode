# Identity and state

## Credentials

Credentials never enter the repository, the mission file or chat. That covers cloud keys,
client secrets, passwords, connection strings, SAS tokens, service account key files and state
files. Never ask the owner for one, and never repeat one you see: say where it is and that it
must be rotated. A preview, a plan file or a state file can hold secrets in plain text, so keep
them outside the repository and delete local copies after the apply.

- **CI** signs in with OIDC federation: the CI job gets a short-lived OpenID Connect token and
  exchanges it for short-lived cloud credentials. No cloud key is stored as a CI secret.
- **A person** signs in with their own short-lived login: `az login`, `aws sso login`,
  `gcloud auth login` (and `gcloud auth application-default login` for Terraform).
- **Secrets the infrastructure needs** (a database password) come from the cloud's secret store
  (Azure Key Vault, AWS Secrets Manager, Google Secret Manager) or are generated by the
  resource itself. Never put them in variables files.

When you find a stored long-lived key, report it as a finding and plan its replacement with OIDC
federation. Do not delete it without approval. Pinned actions and protected CI environments are
in `releasing`'s `reference/ci-cd.md`.

## OIDC federation in CI

The examples use GitHub Actions. The job needs `permissions: id-token: write`. Bind each trust
to the narrowest subject: one repository and one environment
(`repo:<owner>/<repo>:environment:production`), never a whole organization.

| Cloud | Trust in the cloud | Step in the workflow |
| --- | --- | --- |
| Azure | A federated credential on a Microsoft Entra app registration or user-assigned managed identity, subject `repo:<owner>/<repo>:environment:<env>` | `azure/login` with `client-id`, `tenant-id` and `subscription-id` (IDs, not secrets) |
| AWS | An IAM OIDC identity provider for `token.actions.githubusercontent.com`, and a role whose trust policy checks `aud` (`sts.amazonaws.com`) and `sub` | `aws-actions/configure-aws-credentials` with `role-to-assume` and `aws-region` |
| Google Cloud | A workload identity pool and provider with an attribute condition on the repository | `google-github-actions/auth` with `workload_identity_provider` (and `service_account` when you impersonate one) |

Use one identity per environment. The plan identity can read; only the apply identity can
change resources, and only a protected CI environment with required reviewers can use it.
Sources: [GitHub OIDC](https://docs.github.com/en/actions/concepts/security/openid-connect),
[Microsoft Entra workload identity federation](https://learn.microsoft.com/en-us/entra/workload-id/workload-identity-federation),
[AWS IAM OIDC providers](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_providers_create_oidc.html),
[Google Cloud workload identity federation](https://cloud.google.com/iam/docs/workload-identity-federation).

## Remote locked state

Terraform state is remote, locked, encrypted at rest, versioned and readable only by the plan
and apply identities. One state per environment. Never a local state file for a shared
environment, never `*.tfstate` in the repository.

| Backend | Locking | Settings to check |
| --- | --- | --- |
| `azurerm` (Azure Blob Storage) | Blob lease, built in | `use_azuread_auth = true` (no storage key), versioning or soft delete on the container |
| `s3` (Amazon S3) | `use_lockfile = true` (S3 lock file, Terraform 1.10 or later; DynamoDB locking is deprecated) | `encrypt = true`, bucket versioning, block public access |
| `gcs` (Cloud Storage) | Built in | Object versioning, uniform bucket-level access |
| HCP Terraform or Terraform Enterprise | Built in | Workspace per environment, run triggers off for production |

Bicep, CloudFormation and Infrastructure Manager keep state in the cloud service, so there is no
state file to protect. Never run with `-lock=false`, and run `force-unlock` only with the owner.
Sources: [Terraform backends](https://developer.hashicorp.com/terraform/language/backend),
[S3 backend](https://developer.hashicorp.com/terraform/language/backend/s3).
