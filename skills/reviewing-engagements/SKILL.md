# Reviewing engagements

Judge whether a consultant's conclusion and handoff follow from the evidence. A review is not
client decision authority, an authenticated receipt or a guarantee of completeness.

## Bind the shared engagement first

Load `blueprinting` through Amp's skill tool, even on direct entry. Bind to the coordinator base
returned by that tool, not this skill's directory, the engagement directory or a nearby checkout.
Read `reference/composition.md` at that base and follow its dependency and explicit-root checks
before using any helper. If resolution fails or is ambiguous, stop the affected work; do not
search for another installation or install one implicitly. Keep native Amp routing.

## Review the exact material, not the author's assurance

Read the coordinator's `reference/functional-design.md` for coverage, `reference/decisions.md` for
reported business confirmation, and `reference/publication.md` / `reference/exports.md` for handoffs.
Read only applicable references. Keep review read-only unless separately asked to repair.

Inspect original sources, exact candidate revisions, missing evidence and actual renders. Test
whether claims follow from sources, functional rules include exceptions/receiving handoffs, and
the intended reader can identify the decision or action. Distinguish facts, recommendations and
assumptions. Check dates, units, amounts, exclusions and uncertainties across formats. Do not
average away material factual, confidentiality or authority failures with a high visual score.

Return findings tied to source and output locations, severity, consequence and the smallest
needed repair or clarification. Recheck repaired revisions separately. Report what was not
available or inspected. A structurally current record can still be false; a polished artifact
can still be useless. Use an independent context when the mission requires one; loading this
skill in the author's own context does not create independent review or automatic fanout.
